## 难题一：评价审核的性能与准确性平衡

### 问题场景
用户提交餐厅评价后需要内容审核，但 AI 审核耗时 1~3 秒，同步调用会让用户等太久。

### 遇到的困难
1. 单纯的敏感词库无法识别隐晦广告（"加微信"、"私聊"）
2. 评分与内容矛盾难以检测（5星好评却说"难吃"）
3. 需要在不阻塞用户的前提下完成审核

### 解决方案
**两层审核 + 异步处理**：
- **第一层（同步）**：DFA 算法本地快速过滤明显敏感词，<10ms
- **第二层（异步）**：通义千问 AI 语义审核，通过 RabbitMQ 异步处理

```java
// 第一层：DFA 快速过滤
List<String> sensitiveWords = sensitiveWordUtil.check(dto.getContent());
if (!sensitiveWords.isEmpty()) {
    throw new BusinessException("评价内容包含敏感词");
}

// 第二层：发送到 MQ，异步 AI 审核
review.setStatus(ReviewStatus.PENDING);  // 待审核
reviewMapper.insert(review);
rabbitTemplate.convertAndSend("review.exchange", "review.audit", message);
```

### 效果
- 用户提交评价立即返回"审核中"，体验流畅
- 90% 正常评价快速放行，10% 可疑内容 AI 精准判断

## 难题二：RabbitMQ 消息丢失问题

### 问题场景
评价审核消息如果丢失，用户的评价会永远停留在"待审核"状态。

### 遇到的困难
1. 消息发送到交换机可能失败（网络问题）
2. 消息路由到队列可能失败（routing key 写错）
3. 消费者处理失败需要重试，但不能无限重试

### 解决方案
**三重保障机制**：

**1. 生产者端：ConfirmCallback + ReturnsCallback**
```java
// 交换机确认
rabbitTemplate.setConfirmCallback((correlationData, ack, cause) -> {
    if (ack) {
        redisTemplate.delete("mq:msgId:" + msgId);  // 成功，删除备份
    } else {
        handleMessageRetry(msgId);  // 失败，从 Redis 取出重试
    }
});

// 路由失败回退
rabbitTemplate.setReturnsCallback(returned -> {
    handleMessageRetry(msgId);  // 路由失败，重试
});
```

**2. 消息备份到 Redis**
```java
// 发送前先存 Redis
redisTemplate.opsForHash().put("mq:msgId:" + msgId, "message", msgJson);
redisTemplate.opsForHash().put("mq:msgId:" + msgId, "retryCount", 0);
```

**3. 死信队列兜底**
```java
// 正常队列配置死信交换机
@Bean
public Queue reviewAuditQueue() {
    return QueueBuilder.durable("review.audit.queue")
        .withArgument("x-dead-letter-exchange", "review.dlx.exchange")
        .build();
}

// 死信队列消费者
@RabbitListener(queues = "review.audit.dlx.queue")
public void handleFailedReview(ReviewAuditMessage message) {
    // 标记为需要人工审核
    review.setStatus(ReviewStatus.PENDING);
    review.setAiVerdict("AI_ERROR");
    reviewMapper.updateById(review);
}
```

### 效果
- 消息发送失败自动重试 3 次
- 重试失败进入死信队列，转人工审核
- 保证消息不丢失，业务不中断

## 难题三：事务与 MQ 消息发送的顺序问题

### 问题场景
评价写入数据库和发送 MQ 消息需要保证一致性。

### 遇到的困难
```java
@Transactional
public void createReview() {
    reviewMapper.insert(review);       // 写数据库
    rabbitTemplate.convertAndSend();   // 发 MQ
    // 如果这里抛异常，事务回滚，但消息已经发出去了！
}
```

如果事务回滚，消息已发出，消费者会处理一个不存在的 reviewId。

### 解决方案
**用 Spring 事件在事务提交后再发 MQ**：

```java
// 1. 事务内只写库、发布事件
@Transactional
public void createReview() {
    reviewMapper.insert(review);
    eventPublisher.publishEvent(new ReviewCreatedEvent(message, msgId));
}

// 2. 监听器在事务提交后才发 MQ
@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
public void handleReviewCreated(ReviewCreatedEvent event) {
    rabbitTemplate.convertAndSend("review.exchange", "review.audit", event.getMessage());
}
```

### 效果
- 事务成功提交 → 触发监听器 → 发送 MQ
- 事务回滚 → 监听器不触发 → MQ 不发送
- 保证数据库和 MQ 的最终一致性

## 难题四：AI 聊天的会话记忆管理

### 问题场景
用户和 AI 多轮对话时，需要记住上下文，但会话记忆需要持久化到 Redis。

### 遇到的困难
1. LangChain4j 的消息顺序可能被破坏
2. AI 模型要求第一条非系统消息必须是 UserMessage
3. 直接序列化可能导致消息顺序错误

### 解决方案
**自定义 RedisChatMemoryStore，保存前修复消息顺序**：

```java
private List<ChatMessage> fixMessageOrder(List<ChatMessage> messages) {
    // 找到第一条非系统消息
    int firstNonSystemIndex = -1;
    for (int i = 0; i < messages.size(); i++) {
        if (!(messages.get(i) instanceof SystemMessage)) {
            firstNonSystemIndex = i;
            break;
        }
    }
    
    // 如果第一条非系统消息不是 UserMessage，插入占位符
    if (firstNonSystemIndex != -1 && 
        !(messages.get(firstNonSystemIndex) instanceof UserMessage)) {
        messages.add(firstNonSystemIndex, new UserMessage("开始对话"));
    }
    return messages;
}
```

### 效果
- 会话记忆正确保存到 Redis
- 多轮对话上下文连贯
- 避免 AI 模型因消息顺序错误而报错

## 难题五：RAG 知识库的文档切分

### 问题场景
需要将餐厅介绍、菜品信息等文档转换为向量存入 Redis，支持语义检索。

### 遇到的困难
1. 文档过长无法直接向量化（模型有 token 限制）
2. 文档切分不当会丢失关键信息
3. 需要避免重复初始化浪费资源

### 解决方案
**递归切分 + 重叠设计 + Redis 标记**：

```java
// 1. 检查是否已初始化
if (Boolean.TRUE.equals(redisTemplate.hasKey("knowledge:initialized"))) {
    return;  // 跳过
}

// 2. 递归切分文档（最长 500 字符，100 字符重叠）
DocumentSplitter splitter = DocumentSplitters.recursive(500, 100);
List<TextSegment> segments = splitter.splitAll(documents);

// 3. 向量化并存入 Redis
embeddingStore.addAll(segments);

// 4. 标记已初始化
redisTemplate.opsForValue().set("knowledge:initialized", "true", 30, TimeUnit.DAYS);
```

### 效果
- 文档被合理切分，保留上下文
- 重叠设计防止关键信息丢失
- 首次启动初始化，后续启动跳过

## 难题六：N+1 查询问题优化

### 问题场景
查询评价列表时需要关联用户、餐厅、订单等多个表。

### 遇到的困难
简单的循环查询会导致大量数据库访问：
```java
// 错误做法：N+1 查询
for (Review review : reviewList) {
    User user = userMapper.selectById(review.getUserId());  // 每次都查库
    vo.setUserNickname(user.getNickname());
}
```

### 解决方案
**批量查询 + Map 映射**：

```java
// 1. 提取所有 userId
Set<Long> userIds = reviewList.stream()
    .map(Review::getUserId)
    .collect(Collectors.toSet());

// 2. 批量查询用户（只查一次数据库）
List<User> userList = userMapper.selectBatchIds(userIds);

// 3. 构建 Map 映射
Map<Long, User> userMap = userList.stream()
    .collect(Collectors.toMap(User::getId, u -> u));

// 4. 流式组装 VO
List<ReviewVO> voList = reviewList.stream()
    .map(review -> {
        User user = userMap.get(review.getUserId());  // 从 Map 取，不查库
        // ... 组装 VO
    }).collect(Collectors.toList());
```

### 效果
- 原本 N+1 次查询 → 优化为 2 次查询
- 分页查询 100 条数据，从 101 次查询降到 2 次
- 接口响应时间从 500ms 降到 50ms

## 难题七：MCP 工具集成（联网搜索）

### 问题场景
AI 需要实时获取最新信息（餐厅优惠、天气等），不能仅依赖本地知识库。

### 遇到的困难
1. 需要集成第三方 MCP 服务（通义千问 Web Search）
2. API 认证和 SSE 传输协议配置复杂
3. 工具调用需要与 LangChain4j 无缝集成

### 解决方案
**HttpMcpTransport + McpToolProvider**：

```java
// 1. 配置 HTTP SSE 传输
HttpMcpTransport transport = HttpMcpTransport.builder()
    .url("https://open.bigmodel.cn/api/mcp/web_search/sse")
    .header("Authorization", "Bearer " + apiKey)
    .build();

// 2. 创建 MCP 客户端并构建工具提供者
DefaultMcpClient client = new DefaultMcpClient(transport);
McpToolProvider toolProvider = McpToolProvider.builder()
    .mcpClient(client)
    .build();

// 3. 注册到 AI 服务
AiServices.builder(AiHelperService.class)
    .toolProvider(toolProvider)  // AI 可以调用联网搜索
    .build();
```

### 效果
- AI 可以实时搜索最新信息
- 用户问"附近有什么优惠"，AI 能联网查询
- 工具调用由模型自动决定，无需手动触发

## 面试回答技巧

### 开场
> "我在做这个智能美食推荐系统时，遇到了几个比较有挑战的技术问题，印象最深的是..."

### 选择难题
根据面试官的技术栈选择：
- **后端基础**：讲难题二（RabbitMQ 消息可靠性）
- **分布式/高并发**：讲难题六（N+1 查询优化）
- **AI/大模型**：讲难题一（评价审核）或难题七（MCP 集成）
- **数据一致性**：讲难题三（事务与 MQ）

### 回答结构
1. **问题场景**（10秒）：简单说业务背景
2. **遇到的困难**（20秒）：说 2-3 个具体困难点
3. **解决方案**（30秒）：说核心思路，可以带一点代码
4. **效果**（10秒）：量化效果（性能提升、问题解决）

### 注意事项
- 不要背代码，记住核心思路
- 准备 2-3 个难题，根据面试官反应灵活切换
- 如果面试官追问细节，说明他感兴趣，可以深入讲
- 如果面试官没反应，快速收尾，换下一个话题

---

**最后提醒**：这些难题都是真实项目中遇到的，回答时要自然，像讲故事一样，不要像背书！
