```java
// UserServiceImpl.java
@Override
public UserVO register(UserRegisterDTO dto) {
    // 1. 校验手机号是否已注册
    LambdaQueryWrapper<User> wrapper = new LambdaQueryWrapper<>();
    wrapper.eq(User::getPhone, dto.getPhone());
    if (userMapper.selectCount(wrapper) > 0) {
        throw new BusinessException("手机号已注册");
    }

    // 2. 密码加密
    String encodedPassword = passwordEncoder.encode(dto.getPassword());

    // 3. 保存用户
    User user = new User();
    user.setPhone(dto.getPhone());
    user.setPassword(encodedPassword);
    user.setNickname(dto.getNickname());
    userMapper.insert(user);

    // 4. 返回VO（不含密码）
    return BeanUtil.copyProperties(user, UserVO.class);
}
```

### 任务 1.7：AI 业务深度集成（2-3天）

> **前置条件**：任务 1.6 完成（LangChain4j 已集成，AI 调用链路可用）
>
> **核心价值**：让 AI 不只是聊天机器人，而是真正嵌入业务流程——自动处理数据、替代人工操作

#### 📋 任务清单

- [ ] **功能一：AI 评价情感分析 + 自动审核**

  **背景**：评价系统目前是人工审核（`status=0 待审核`），效率低。
  
  **实现思路**：
  - 用户提交评价后，在 `ReviewServiceImpl.createReview()` 末尾**异步触发** AI 审核
  - 使用 LangChain4j 的**结构化输出（Structured Output）**，让 AI 返回 JSON 格式结论：
    ```json
    {
      "verdict": "APPROVE | REJECT | MANUAL_REVIEW",
      "reason": "内容正常，文字与评分一致",
      "tags": ["服务热情", "环境一般", "性价比高"]
    }
    ```
  - AI 判断三种情况：
    - `APPROVE`：内容正常且文字与星级一致 → 自动将 `status` 改为 1（已通过）
    - `REJECT`：含广告/侮辱性语言 → 自动将 `status` 改为 2（已拒绝）
    - `MANUAL_REVIEW`：文字与评分严重矛盾（说"很好吃"但打1星）→ 保持 `status=0`，等人工处理
  - 将情感标签 `tags` 以 JSON 格式存入 `review` 表新增字段 `ai_tags`
  - 异步实现方式：Spring `@Async` 注解（简单）或后续接 RabbitMQ（升级方案）

  **新增字段（review 表）**：
  - `ai_tags` VARCHAR(500) - AI 提取的情感标签（JSON 数组）
  - `ai_verdict` VARCHAR(20) - AI 审核结论（APPROVE/REJECT/MANUAL_REVIEW）

- [ ] **功能二：AI 餐厅评价摘要生成**

  **背景**：用户在餐厅详情页只能看到评价列表，无法快速了解整体口碑。
  
  **实现思路**：
  - 在 `RestaurantServiceImpl.getRestaurantById()` 中，拼装餐厅 VO 时额外附带 AI 摘要
  - AI 摘要单独缓存（key: `restaurant:ai:summary:{id}`，TTL 24小时），不影响主缓存逻辑
  - 摘要生成触发时机：
    - 缓存不存在时，**同步**生成（首次访问）
    - 有新评价通过审核时，**异步刷新**缓存（在 `approveReview` 方法末尾触发）
  - AI 生成内容格式：
    ```json
    {
      "summary": "用户普遍认为招牌红烧肉火候到位，服务热情，环境稍显嘈杂，建议提前预约。",
      "highlights": ["招牌菜值得一试", "服务热情", "性价比高"],
      "warnings": ["环境嘈杂", "等位时间较长"]
    }
    ```
  - `RestaurantVO` 新增 `aiSummary` 字段，前端在详情页展示

#### 🎯 验收标准
- 提交评价后，`status` 字段在几秒内自动更新（无需人工干预），`ai_tags` 有情感标签数据
- 对"说好话打低分"或包含广告的评价，AI 能正确识别并处理
- 餐厅详情接口返回 `aiSummary` 字段，内容准确反映评价整体倾向
- 餐厅有新评价通过后，24小时内摘要自动刷新

#### 📝 实现位置
- 情感分析服务: `cn/zjw/aiservice/ReviewAnalysisService.java`（新建，`@AiService` 接口，使用结构化输出）
- 评价服务修改: `cn/zjw/service/impl/ReviewServiceImpl.java`（`createReview` 末尾触发异步分析）
- 摘要服务: `cn/zjw/aiservice/RestaurantSummaryService.java`（新建）
- 餐厅服务修改: `cn/zjw/service/impl/RestaurantServiceImpl.java`（`getRestaurantById` 附加摘要）
- VO 修改: `RestaurantVO` 新增 `aiSummary` 字段

#### 💡 技术要点
- **结构化输出**：LangChain4j 支持让 AI 返回 Java 对象（非自由文本），通过定义 Java record/class 作为返回类型实现，比解析字符串可靠得多
- **异步不阻塞**：情感分析是 AI 调用，耗时 1-3 秒，必须异步，不能让用户等待
- **摘要的输入控制**：只取最近 20 条已通过审核的评价，避免 token 超限，同时保证内容新鲜度
- **降级处理**：AI 调用失败时，`aiSummary` 返回 `null`，前端不展示该模块，不影响主流程
